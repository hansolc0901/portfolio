# 최한솔 포트폴리오

상명대학교 그린스마트시티학과 최한솔의 포트폴리오 웹사이트입니다.
화면(프론트엔드)과 데이터(백엔드)를 분리해, 나중에 데이터베이스나 다른 프로그램을
붙일 수 있도록 구성했습니다.

## 폴더 구조

```
.
├── data/portfolio.json     모든 내용의 원본. 여기만 고치면 화면·PDF가 함께 바뀝니다
│
├── backend/                Node.js + Express API 서버
│   ├── server.js           서버를 켜는 곳
│   ├── scripts/            관리자 비밀번호 정하기
│   └── src/
│       ├── config.js       설정값 모음 (환경변수는 여기서만 읽습니다)
│       ├── app.js          서버 조립
│       ├── routes/         주소(URL) 정의
│       ├── repositories/   ★ 데이터를 어디서 읽을지 정하는 곳
│       ├── projects/       ★ 입력 칸의 정의와 검사 규칙
│       ├── auth/           비밀번호 확인, 로그인 출입증
│       ├── services/       배포용 파일 다시 만들기
│       └── middleware/     로그인 확인, 오류 처리
│
├── frontend/               화면
│   ├── index.html          내용이 비어 있는 뼈대
│   ├── styles.css
│   ├── js/
│   │   ├── api.js          데이터 가져오기 (백엔드 → 실패하면 내장 데이터)
│   │   ├── render.js       데이터 → 화면
│   │   ├── ui.js           버튼·모달·스크롤 효과
│   │   └── main.js         실행 순서
│   └── admin/              관리자 페이지 (로그인 필요)
│
├── build.py                전부 합쳐 index.html 한 개로 만듭니다
└── index.html              배포용 결과물 (파일 하나로 동작)
```

## 두 가지 실행 방법

이 사이트는 **서버가 있어도, 없어도** 동작합니다.

| 방법 | 여는 법 | 데이터 출처 |
|---|---|---|
| 서버 모드 | 백엔드를 켜고 `http://localhost:4000` | 백엔드 API |
| 파일 모드 | `index.html` 을 더블클릭 | 파일에 내장된 데이터 |

화면은 먼저 백엔드에 물어보고, 2초 안에 답이 없으면 내장 데이터로 자동 전환합니다.
그래서 기존처럼 `index.html` 파일 하나만 올려도 그대로 쓸 수 있습니다.

## 서버 켜기

```bash
cd backend
npm install                          # 처음 한 번만
npm run set-password -- 내비밀번호    # 처음 한 번만
npm start
```

켜지면 `http://localhost:4000` 에서 화면이 열립니다. 끌 때는 `Ctrl + C` 입니다.
파일을 고칠 때마다 자동으로 다시 켜려면 `npm run dev` 를 쓰세요.

## 관리자 페이지

서버를 켠 뒤 `http://localhost:4000/admin` 으로 들어갑니다.

작업물을 **제목 · 내가 한 역할 · 설명 · 날짜 · 참여인원수 · 참고사항** 으로 관리합니다.
빈칸에는 옅은 색으로 예시가 보이고, 입력하면 사라집니다.

### 초안과 공개

두 선택지는 설명과 함께 카드로 나란히 보이고, 고른 쪽에 따라 저장 버튼의 이름이 바뀝니다.

| | 빈칸 | 방문자 | 관리자 화면 | 저장 버튼 |
|---|---|---|---|---|
| **초안** | 비워 둬도 저장됨 | 보이지 않음 | 보임 | `임시저장` |
| **공개** | 참고사항 외 모두 필수 | 보임 | 보임 | `공개로 저장` |

초안은 서버에 저장되므로 **다음에 다시 들어와도 적어둔 내용이 그대로 남아 있습니다.**
빠진 칸이 있으면 목록에 `빈 칸 N개` 로 표시됩니다.

### 중복 확인

같은 작업물이 두 번 들어가지 않도록, 저장할 때 **제목이 같은 작업물이 있는지** 확인합니다.

판단 기준은 하나입니다 — **제목이 같으면 중복.**
앞뒤 공백, 사이 띄어쓰기 칸 수, 영문 대소문자 차이는 무시합니다.
제목이 비어 있으면 비교하지 않으므로, 제목 없는 초안은 여러 개 만들 수 있습니다.

겹치는 제목이 있으면 저장을 멈추고 세 가지를 제안합니다.

| 선택 | 결과 |
|---|---|
| **기존 것에 합치기** | 기존 작업물의 **빈 칸만** 지금 입력한 내용으로 채웁니다. 이미 적혀 있던 값은 덮어쓰지 않습니다. 고치던 중이었다면 그 항목은 지워집니다. |
| **따로 저장** | 중복을 허용하고 별개로 저장합니다. |
| **취소** | 저장하지 않고 폼으로 돌아갑니다. |

이미 쌓여 있는 중복은 목록에 `중복` 배지로 표시됩니다. 그 작업물을 열고 저장을 누르면
같은 제안이 뜨므로, 나중에라도 합칠 수 있습니다.

사진·영상이 달린 작업물은 합치면서 지우지 않습니다. 실수로 없애면 되돌리기 어렵기 때문입니다.

판단 규칙은 `backend/src/projects/duplicates.js` 한 곳에만 있습니다.

### 저장하지 않은 내용 지키기

저장 버튼을 누르기 전의 입력도 **브라우저에 자동으로 보관**됩니다.

- 입력을 잠깐 멈추면 자동 보관되고, 화면에 `저장하지 않은 변경이 있습니다` 라고 표시됩니다.
- 창을 닫았다 다시 열면 `불러오기 / 버리기` 를 물어봅니다.
- 다른 작업물로 이동하거나 로그아웃할 때 저장하지 않은 내용이 있으면 한 번 더 확인합니다.
- 서버에 저장하면 브라우저에 보관해 둔 내용은 자동으로 정리됩니다.

자동 보관은 그 브라우저 안에만 남습니다. 다른 기기에서는 보이지 않으므로,
오래 쓸 내용은 `임시저장` 을 눌러 서버에 넣어 두세요.

### 비밀번호

```bash
cd backend
npm run set-password -- 새비밀번호
```

비밀번호 원문은 어디에도 저장되지 않습니다. 되돌릴 수 없는 형태(scrypt 해시)로
`backend/.env` 에만 들어가고, `.env` 는 git 에 올라가지 않습니다.
화면으로도 나가지 않습니다. 로그인하면 임시 출입증만 받습니다.

다섯 번 틀리면 10분 동안 잠깁니다.

### 로그인은 유지되지 않습니다

**관리자 페이지에 들어갈 때마다 비밀번호를 새로 입력합니다.**

출입증(로그인 상태)을 브라우저에 저장하지 않고 화면이 열려 있는 동안 메모리에만 두기 때문입니다.

| 상황 | 결과 |
|---|---|
| 창을 닫음 | 로그인 사라짐. 서버에 남은 출입증도 그 순간 함께 없어짐 |
| 새 창·새 탭으로 열기 | 다시 로그인 |
| 새로고침(F5) | 다시 로그인 |
| 뒤로 가기로 되돌아옴 | 다시 로그인 |
| 30분 동안 아무 동작 없음 | 서버의 출입증이 저절로 없어짐 (쓰는 동안에는 계속 미뤄짐) |

관리자 응답에는 `Cache-Control: no-store` 를 붙여 브라우저에 남지 않게 합니다.
비밀번호 입력칸은 읽는 즉시 비우고, 브라우저가 기억하지 않도록 `autocomplete="off"` 로 두었습니다.

로그인이 풀려도 **쓰던 내용은 자동 보관으로 남아 있으므로**, 다시 로그인한 뒤 불러오면 됩니다.

무활동 시간은 `backend/.env` 의 `SESSION_TTL_MINUTES` 로 바꿀 수 있습니다.

### 저장한 내용을 배포용 파일에 반영하기

관리자 페이지의 **'배포용 파일 다시 만들기'** 버튼을 누르면 `python build.py` 가
실행되어 `index.html` 이 새로 만들어집니다. 초안은 이 파일에 들어가지 않습니다.

버튼이 동작하지 않으면 `backend/.env` 의 `PYTHON_BIN` 을 `python3` 또는
파이썬 전체 경로로 바꿔 주세요.

## 배포용 파일 만들기

`frontend/` 나 `data/portfolio.json` 을 고친 뒤 실행합니다.

```bash
python build.py
```

두 가지를 만듭니다.

1. `frontend/assets/` — 판넬 원본(31MB)을 웹용 크기로 줄인 사진
2. `index.html` — HTML·CSS·JS·데이터·사진을 전부 합친 파일 하나

## 인터넷에 올리기 (Vercel)

주소: <https://portfolio-hazel-one-63.vercel.app/>

GitHub 저장소가 Vercel 에 연결되어 있어서, `main` 에 올리면 자동으로 다시 배포됩니다.

```bash
python build.py                 # 1. 배포용 index.html 다시 만들기
git add -A && git commit -m "..."   # 2. 저장
git push                        # 3. 올리기 → 1~2분 뒤 사이트 반영
```

관리자 페이지에서 고쳤다면 **'배포용 파일 다시 만들기' 버튼을 먼저 누른 뒤** 올려야
바뀐 내용이 사이트에 나옵니다.

### 배포되는 것과 안 되는 것

`.vercelignore` 에 적힌 대로, 인터넷에는 **`index.html` 과 `summerschool.mp4` 두 개만** 올라갑니다.
화면·글씨·사진이 모두 `index.html` 안에 들어 있어 다른 파일이 필요 없습니다.

| | 인터넷 | GitHub |
|---|---|---|
| `index.html`, `summerschool.mp4` | 올라감 | 올라감 |
| `backend/`, `frontend/`, `data/`, `build.py` | **안 올라감** | 올라감 |

관리자 페이지는 서버가 있어야 동작하므로 인터넷에는 올리지 않습니다.
주소를 직접 쳐도 404 가 납니다. 내 컴퓨터에서 서버를 켰을 때만 쓸 수 있습니다.

초안도 `index.html` 에 들어가지 않으므로 방문자에게 보이지 않습니다.

## API 목록

응답은 항상 `{ "data": ... }` 모양입니다. 오류는 `{ "error": { "status", "message" } }` 입니다.

| 주소 | 내용 |
|---|---|
| `GET /api/health` | 서버 상태와 현재 데이터 출처 |
| `GET /api/portfolio` | 전체 |
| `GET /api/profile` | 인적사항 |
| `GET /api/projects` | 작업물 목록 |
| `GET /api/projects/:id` | 작업물 하나 |
| `GET /api/credentials` | 활동·자격 목록 |
| `GET /api/credentials/:id` | 활동·자격 하나 |

위 주소는 **공개된 작업물만** 돌려줍니다. 초안은 나오지 않습니다.

### 관리자용 (로그인 필요)

`/login` 만 누구나 부를 수 있고, 나머지는 `Authorization: Bearer 출입증` 이 있어야 합니다.

| 주소 | 내용 |
|---|---|
| `POST /api/admin/login` | 비밀번호를 보내고 출입증을 받음 |
| `POST /api/admin/logout` | 출입증 버리기 (창을 닫을 때도 자동으로 부릅니다) |
| `GET /api/admin/fields` | 입력 칸의 정의 (화면이 폼을 만들 때 사용) |
| `GET /api/admin/projects` | 작업물 목록 (**초안 포함**) |
| `GET /api/admin/projects/:id` | 작업물 하나 |
| `POST /api/admin/projects` | 새로 만들기 |
| `PUT /api/admin/projects/:id` | 수정하기 |
| `POST /api/admin/projects/:id/merge` | 중복 합치기 (남길 작업물의 빈 칸을 채우고 중복 항목을 지움) |
| `POST /api/admin/build` | 배포용 index.html 다시 만들기 |

새로 만들기와 수정하기는 제목이 겹치면 `409` 로 멈추고, 겹치는 작업물을 함께 알려 줍니다.
그대로 저장하려면 본문에 `"allowDuplicate": true` 를 넣어 다시 보냅니다.

작업물 목록(`GET /api/admin/projects`)에는 제목이 겹치는 항목에 `isDuplicate: true` 가 붙습니다.

단독 삭제는 없습니다. 지우고 싶은 작업물은 **초안**으로 바꾸면 방문자에게 보이지 않고,
중복이라면 합치기로 정리할 수 있습니다.

## 나중에 데이터베이스를 붙일 때

**고칠 파일은 한 개입니다.** `backend/src/repositories/dbRepository.js` 를 채우면 됩니다.

라우트와 화면 코드는 데이터가 어디서 오는지 모르게 만들어 두었기 때문에,
JSON 파일에서 DB 로 바꿔도 다른 파일은 고치지 않습니다.

1. 드라이버 설치 — 예) `cd backend && npm install pg`
2. `dbRepository.js` 위쪽 주석의 "표 설계" 대로 표를 만듭니다
3. 주석 처리된 예시를 참고해 일곱 함수를 채웁니다
   - 읽기: `getPortfolio`, `getProfile`, `getProjects`, `getProject`, `getCredentials`
   - 쓰기: `createProject`, `updateProject`
4. `backend/.env` 에서 `DATA_SOURCE=db`, `DATABASE_URL=...` 로 바꿉니다
5. 서버를 다시 켭니다

함수의 이름이나 반환 모양이 약속과 다르면 서버가 켜질 때 바로 알려 줍니다.
약속은 `backend/src/repositories/portfolioRepository.js` 에 적혀 있습니다.

## 입력 칸을 늘리고 싶을 때

`backend/src/projects/projectFields.js` 에 한 줄만 추가하면 됩니다.
관리자 화면의 폼, 예시 문구, 필수 검사가 모두 이 파일 하나를 보고 만들어지므로
화면과 서버의 규칙이 어긋날 수 없습니다.

## 설정

`backend/.env.example` 을 복사해 `backend/.env` 로 만든 뒤 값을 채웁니다.
`.env` 는 git 에 올라가지 않습니다.
